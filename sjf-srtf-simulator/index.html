THE CORE IDEA / 02

Same family. Different decisions.

SJF looks at the next job's burst time. SRTF repeatedly considers how much execution time each ready process still needs.

Shortest Job First

At a scheduling decision, choose the available process with the smallest original burst time. After it starts, it continues until completion.

Shortest Remaining Time First

At each decision point, choose the process with the smallest remaining CPU time. A newly arrived shorter process can interrupt the current one.

KEY RULEPreemption is allowed
MEASURE THE OUTCOME

Four metrics explain the schedule.

These formulas are calculated per process after the execution timeline is built. “First start” means the first time the process receives the CPU.

CTCompletion Time

Time when a process finishes execution.

CT = finishing time
TATTurnaround Time

Total elapsed time between arrival and completion.

TAT = CT − AT
WTWaiting Time

Total time spent waiting for CPU service.

WT = TAT − BT
RTResponse Time

Time until the process first gets the CPU.

RT = first start − AT
ALGORITHM LOGIC

Pseudocode, simplified

{ }
Non-Preemptive SJF
while processes remain:
  ready = arrived, unfinished processes
  if ready is empty:
    jump to next arrival time
  else:
    choose ready process with
      shortest burst time
    run it until completion
    record completion time
calculate CT, TAT, WT and RT
Preemptive SJF / SRTF
while processes remain:
  ready = arrived processes with
          remaining time > 0
  if ready is empty:
    advance to next arrival
  else:
    choose smallest remaining time
    execute for one time unit
    if remaining time reaches zero:
      record completion time
repeat until all processes finish
calculate CT, TAT, WT and RT

Implementation note: SRTF is simulated in integer time units. Adjacent intervals belonging to the same process are merged for a cleaner Gantt chart.

From paper to project.

The simulator turns scheduling theory into a controlled experiment: use identical process inputs, run two algorithms, and compare measurable outcomes.

ENGINEERING NOTES / 05

Scope & assumptions.

A transparent simulator is easier to evaluate: these boundaries clarify exactly what is—and is not—being modelled.

✓

Included

  • Single CPU scheduling model
  • Integer arrival and burst times
  • Preemption when a strictly shorter remaining-time job wins
  • Idle intervals when no process is ready
  • CT, TAT, WT, RT and average metrics
!

Not modelled yet

  • Real operating-system process control
  • Actual CPU burst prediction
  • Context-switch duration and its cost
  • Multicore scheduling and I/O bursts
  • Priority, deadline or fairness policies
↗

Future extensions

  • FCFS, Round Robin and Priority Scheduling
  • Configurable context-switch overhead
  • Starvation and fairness indicators
  • Animated step-by-step execution
  • Adaptive scheduling research variants
